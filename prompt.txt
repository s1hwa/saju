너는 시니어 프론트엔드/데스크톱 애플리케이션 개발자다.

내가 기존에 사용 중인 Excel 기반 사주 상담 도구를 Windows용 상담 프로그램으로 재구현하려고 한다.

프로젝트의 가장 중요한 원칙은 다음 두 가지다.

1. 기존 Excel의 계산 결과를 정확하게 재현할 것
2. Excel 느낌을 없애고, 손님에게 보여줘도 전문적으로 보이는 세련된 상담 프로그램으로 만들 것

아래 요구사항을 기준으로 먼저 기존 Excel을 분석한 뒤 프로젝트를 설계하고 구현해라.

## 1. 원본 파일

프로젝트 폴더에 기존 Excel 파일을 함께 넣을 예정이다.

파일명 예시:

`기본형식 흑백 2.xlsx`

이 Excel에는 여러 시트가 있을 수 있지만 첫 번째 시트만 분석 및 구현 대상으로 한다.

현재 첫 번째 시트명은 Excel상 `Sheet1`이 아닐 수도 있으므로, 시트 이름이 아니라 workbook의 첫 번째 worksheet를 기준으로 처리해라.

다른 시트는 무시해라.

## 2. 프로그램 목적

이 프로그램은 사주 상담 가게에서 사장님이 손님과 상담하면서 사용하는 프로그램이다.

현재는 Excel 셀에 값을 입력하면 여러 수식에 의해 연도, 나이, 심리, 수단, 재물, 명예 등의 값이 계산되고 최종적으로 그래프가 생성된다.

이 Excel의 계산 기능을 일반 사용자가 직접 Excel을 열지 않아도 사용할 수 있도록 별도의 Windows 실행 프로그램으로 만들고 싶다.

최종적으로는 다음과 같은 흐름이어야 한다.

프로그램 실행
→ 상담 기본정보 입력
→ 자동 계산
→ 전문적인 상담 결과 화면 표시
→ 그래프 확인
→ PDF 저장 / 인쇄 / 이미지 저장

## 3. 기술 스택

다음 기술을 우선 사용해라.

* React
* TypeScript
* Electron
* Vite
* Apache ECharts

프로그램은 최종적으로 Windows에서 실행 가능한 `.exe` 형태로 빌드할 수 있어야 한다.

다음 조건을 만족해야 한다.

* 인터넷 연결 불필요
* 서버 불필요
* 로그인 불필요
* Microsoft Excel 설치 불필요
* 원본 Excel 파일을 실행 시 열지 않아도 됨

즉 Excel은 개발 단계에서 기존 계산 규칙을 분석하기 위한 자료로만 사용하고, 최종 프로그램은 Excel 없이 독립 실행되어야 한다.

## 4. 가장 먼저 해야 할 작업

UI부터 만들지 마라.

먼저 Excel 첫 번째 시트를 완전히 분석해라.

다음 항목을 구분해 정리해야 한다.

### A. 사용자가 직접 입력하는 값

현재 확인된 주요 값은 다음과 같다.

* 이름
* 입춘의 년도
* 나이

`수단 및 재물의 간격 년수`라는 값도 존재하지만 현재 버전에서는 우선 `10`으로 고정한다.

따라서 이 값은 사용자에게 입력받지 않고 내부 상수로 관리해도 된다.

단, 향후 변경할 가능성이 있으므로 코드에 magic number로 여러 곳에 직접 넣지 말고 별도 config/constants 파일에 선언해라.

### B. Excel 수식으로 자동 계산되는 값

Excel에서 자동 계산되는 모든 값을 찾아라.

예:

* 절기별 연도
* 절기별 나이
* 심리
* 수단
* 재물
* 명예
* 그래프에 사용되는 모든 데이터

사용자에게 이 값들을 직접 입력시키면 안 된다.

기존 Excel 함수나 값 배열을 분석해서 TypeScript 로직으로 옮겨라.

## 5. 절대 중요한 계산 원칙

Excel의 기존 결과가 정답이다.

임의로 계산 방식을 단순화하거나 사주 지식을 이용해 새로운 계산 공식을 만들지 마라.

예를 들어 연도 계산이 단순히 항상 `+2, +3, +2, +3` 패턴처럼 보인다고 해서 임의로 일반화하지 마라.

실제 Excel의 각 셀 수식을 확인해서 계산 규칙을 그대로 재현해야 한다.

일부 구간에서 수식 패턴이 달라진다면 그 차이도 그대로 분석해야 한다.

Excel 작성자의 실수처럼 보이는 부분도 임의로 수정하지 마라.

의도가 불분명하거나 동일한 패턴에서 특정 셀만 수식이 다른 등 이상한 부분을 발견하면:

1. 해당 셀 위치
2. 현재 수식
3. 전후 셀 수식
4. 왜 이상하다고 판단했는지

를 정리해서 나에게 질문해라.

확실하지 않은 사주 계산 규칙을 추측해서 구현하지 마라.

## 6. Excel 분석 결과 문서화

구현 전에 다음 내용을 Markdown 문서로 작성해라.

예:

`docs/excel-analysis.md`

여기에 다음 내용을 기록해라.

* 첫 번째 시트명
* 실제 사용 영역
* 사용자가 입력하는 셀
* 자동 계산 셀
* 각 계산식의 역할
* 절기 배열
* 연도 계산 규칙
* 나이 계산 규칙
* 심리 계산/데이터
* 수단 계산/데이터
* 재물 계산/데이터
* 명예 계산/데이터
* 그래프가 참조하는 범위
* 특이하거나 의심되는 수식
* 구현 시 주의사항

수식 하나하나를 의미 없이 나열하기보다 프로그램 로직으로 이해할 수 있게 정리해라.

## 7. 계산 로직 구조

Excel 로직을 React 컴포넌트 안에 직접 작성하지 마라.

UI와 계산 로직을 완전히 분리해라.

예를 들어 다음과 같은 구조를 권장한다.

실제 Excel 구조에 맞게 더 좋은 구조가 있다면 수정해도 된다.

단,

`입력 → 계산 엔진 → 결과 데이터 → UI`

흐름은 명확하게 분리해라.

## 8. 상담 입력 화면

프로그램을 실행하면 복잡한 메뉴 대신 바로 상담 정보 입력 화면이 보여야 한다.

기본적으로 입력받을 값:

* 이름
* 입춘의 년도
* 나이

수단·재물 간격은 현재 10년 고정.

UI 예시:

┌────────────────────────────────┐
│          인생 흐름 분석        │
│                                │
│ 이름          [             ]  │
│ 입춘의 년도   [             ]  │
│ 나이          [             ]  │
│                                │
│          [ 분석하기 ]          │
└────────────────────────────────┘

Excel 셀 같은 디자인은 사용하지 마라.

손님 앞에서 사용해도 자연스러운 전문 프로그램처럼 디자인해라.

## 9. 상담 결과 화면

분석하기 버튼을 누르면 별도의 결과 화면으로 이동한다.

상단에는 다음 정보가 보여야 한다.

예:

홍길동 님의 인생 흐름

입춘 기준 1995년

그 아래 화면의 대부분을 큰 그래프가 차지하게 한다.

## 10. 그래프 요구사항

Apache ECharts를 이용한다.

그래프에는 다음 네 개의 흐름을 표시한다.

* 심리
* 수단
* 재물
* 명예

각 항목은 개별적으로 ON/OFF할 수 있어야 한다.

예:

[✓ 심리] [✓ 수단] [✓ 재물] [✓ 명예]

특정 항목을 클릭하면 해당 선만 숨기거나 다시 보여준다.

Excel에서 행을 숨기는 방식보다 훨씬 편하게 구현한다.

## 11. X축 정보

각 시점에는 다음 정보가 모두 필요하다.

* 절기
* 연도
* 나이

손님에게도 세 정보가 모두 보여야 한다.

예:

입춘
1995
21세

절기는 Excel에 들어 있는 기존 순서를 그대로 사용한다.

절기 목록이나 배치 순서를 임의로 수정하지 마라.

## 12. 그래프 Tooltip

그래프의 특정 위치에 마우스를 올리면 상세 정보가 표시되어야 한다.

예:

입춘

1995년
21세

심리 +12.5
수단 +10
재물 -5
명예 +15

현재 ON/OFF 여부와 관계없이 UX상 자연스러운 방식으로 보여줘라.

숫자가 너무 길 경우 적절하게 포맷팅해라.

## 13. 디자인 방향

디자인 키워드는:

* 세련됨
* 전문적
* 깔끔함
* 차분함
* 현대적인 동양 상담소
* 데이터 분석 프로그램처럼 신뢰감 있음

피해야 할 디자인:

* 전형적인 Excel UI
* 과도한 금색
* 용무늬
* 한자 장식 남발
* 촌스러운 사주 프로그램
* 과한 그라데이션
* 너무 많은 그림자
* 지나친 애니메이션

추천 방향:

* 웜 화이트 / 아이보리 / 아주 옅은 웜그레이 배경
* 차콜 계열 텍스트
* 저채도 포인트 컬러
* 넉넉한 여백
* 카드 기반 레이아웃
* 큰 그래프
* 적절한 둥근 모서리
* 가독성 높은 한글 폰트

디자인 시스템도 간단하게 정리해서 적용해라.

## 14. 결과 화면 기능

결과 화면에는 최소 다음 기능이 필요하다.

* 정보 수정
* 새 상담
* 심리 ON/OFF
* 수단 ON/OFF
* 재물 ON/OFF
* 명예 ON/OFF
* PDF 저장
* 인쇄
* 이미지 저장

`새 상담`을 누르면 기존 입력값을 초기화하고 새 상담을 시작할 수 있어야 한다.

## 15. PDF 출력

화면을 단순 스크린샷으로 PDF로 만들지 마라.

인쇄/PDF 전용 레이아웃을 따로 만들어라.

A4 기준으로 보기 좋은 상담 결과지 형태여야 한다.

가능하면 그래프 특성상 A4 가로 방향을 우선 검토해라.

PDF에는 최소 다음 내용이 포함되어야 한다.

* 상담소명 또는 프로그램명
* 고객 이름
* 상담 날짜
* 입춘 기준년도
* 그래프
* 심리 / 수단 / 재물 / 명예 범례
* 절기
* 연도
* 나이

향후 가게 로고 및 상호를 받을 예정이므로 쉽게 교체할 수 있게 구성해라.

## 16. 인쇄

Windows 기본 인쇄 기능을 이용해 바로 출력할 수 있어야 한다.

PDF 출력 레이아웃과 실제 인쇄 결과가 최대한 동일하게 나오도록 한다.

## 17. 이미지 저장

상담 결과 그래프 또는 결과지를 PNG 형태로 저장할 수 있게 한다.

손님에게 카카오톡 등으로 전달할 가능성이 있으므로 이미지가 깨지지 않게 충분한 해상도로 출력한다.

## 18. 상담기록 저장

현재 1차 버전에서는 필수 기능이 아니다.

SQLite, 서버, 회원관리 등은 우선 구현하지 마라.

단, 향후 다음 기능을 붙일 수 있도록 구조를 망가뜨리지 마라.

* 최근 상담 목록
* 고객별 상담 기록
* 과거 상담 다시 열기

현재 프로젝트에서는 기능 범위를 불필요하게 키우지 않는 것이 중요하다.

## 19. 검증

이 프로젝트에서 가장 중요한 테스트다.

원본 Excel과 프로그램에 동일한 입력값을 넣었을 때:

* 절기
* 연도
* 나이
* 심리
* 수단
* 재물
* 명예

값이 모두 동일해야 한다.

가능하다면 Excel의 여러 테스트 입력값을 사용해 자동 테스트 케이스도 작성해라.

예:

input:

* 입춘년도: XXXX
* 나이: XX

expected:

* years: [...]
* ages: [...]
* psychology: [...]
* means: [...]
* wealth: [...]
* honor: [...]

계산 로직은 React 화면을 실행하지 않고도 테스트할 수 있어야 한다.

## 21. 개발 과정에서 지켜야 할 것

기존 코드를 수정할 때 무작정 큰 파일 하나에 모든 기능을 넣지 마라.

TypeScript 타입을 적극적으로 사용해라.

`any` 사용은 최소화한다.

UI 값과 계산용 값을 구분해라.

상수는 constants로 분리한다.

반복되는 로직을 복사해서 사용하지 마라.

사주 로직에 대한 근거 없는 추측을 하지 마라.

기존 Excel을 정답 기준으로 삼는다.

Excel 계산 결과와 다른 값이 나오면 UI 작업보다 계산 문제를 먼저 해결한다.

## 22. 질문이 필요한 경우

다음 상황에서는 임의로 판단하지 말고 나에게 질문해라.

* Excel 수식 패턴이 중간에 갑자기 달라지는 경우
* 참조 셀이 비어 있는데 수식이 존재하는 경우
* 동일 역할로 보이는 셀들의 수식이 서로 다른 경우
* 그래프에는 사용되지만 의미를 알 수 없는 값이 있는 경우
* 숨겨진 행이나 열이 계산에 영향을 주는 경우
* 특정 숫자가 고정값인지 계산값인지 판단하기 어려운 경우
* Excel 오류로 보이는 수식을 발견한 경우

질문할 때는 단순히 “이게 뭔가요?”라고 하지 말고,

“OO셀에는 `=...`가 있고 앞뒤 셀은 `=...` 패턴인데 이 셀만 다릅니다. 이 차이가 의도된 계산 규칙인지 확인 부탁드립니다.”

처럼 실제 셀과 수식을 근거로 질문해라.

## 23. 현재 확정된 비즈니스 규칙

현재 확정된 내용은 다음과 같다.

* 첫 번째 시트만 구현
* 사장님이 상담 때마다 기본 입력값을 직접 입력
* 심리/수단/재물/명예 등 나머지 값은 Excel 로직으로 자동 계산
* 수단 및 재물 간격 년수는 현재 10으로 고정
* 절기 / 연도 / 나이는 모두 손님에게 표시
* 심리 / 수단 / 재물 / 명예 그래프 모두 필요
* 네 그래프는 각각 표시/숨김 가능
* PDF 저장 필요
* 인쇄 필요
* 이미지 저장 필요
* 상담 기록 저장은 1차 버전에서 제외
* 프로그램은 사장님 Windows PC에서만 실행되면 됨
* 오프라인 실행 가능해야 함

## 24. 최종 목표

이 프로젝트의 목표는 단순히 Excel을 웹 화면으로 옮기는 것이 아니다.

현재의:

Excel 실행
→ 셀 위치 찾기
→ 값 입력
→ 수식 확인
→ 행을 숨기거나 표시
→ Excel 그래프 보여주기

과정을:

상담 프로그램 실행
→ 고객 정보 입력
→ 분석하기
→ 전문적인 상담 결과 그래프
→ 필요한 흐름만 선택해서 설명
→ PDF 또는 인쇄로 고객에게 제공

하는 경험으로 바꾸는 것이 목표다.

기존 Excel의 계산 정확성은 그대로 유지하면서 UX와 디자인만 전문 상담 프로그램 수준으로 개선해라.

우선 코딩을 시작하기 전에 Excel 첫 번째 시트를 분석하고 `docs/excel-analysis.md`를 작성해라.

분석 과정에서 계산 규칙이 명확하면 바로 계산 엔진 구현까지 진행하고, 실제로 판단이 필요한 부분만 질문해라.
