# 인생 흐름 주기 — Excel 기반 상담 업무의 Windows 프로그램 전환

사주 상담소의 기존 Excel 양식을 분석해 상담 정보 입력부터 그래프 비교, 결과지 저장·인쇄까지 연결한 Windows 기반 상담 프로그램.

이름·입춘 기준 연도·나이를 입력하면 심리·수단·재물·명예의 흐름을 계산하여 그래프로 표시.

![심리·수단·재물·명예 통합 결과 화면](docs/images/result-all.png)

## 2. 핵심 문제 해결

구현·검증 과정에서 발견한 기술적 문제


### 1. Excel 시점 정보와 흐름 값의 불일치 분석

- 초기 분석에서 첫 번째 시트의 절기·연도·나이 정보는 38개인데 흐름 값은 39개임을 확인함. 같은 열끼리 연결하면 흐름의 초기 값과 시점이 어긋나므로, 값의 시작 위치와 10년 간격 관계를 비교해 대응 기준을 찾음.

- 초기 이식에서는 의뢰인과 합의해 Excel의 `C:AN` 시점 정보 38개에 `B:AM` 흐름 값 38개를 연결함. 대응 시점이 없는 마지막 `AN` 흐름 값은 사용하지 않고 판단 기록에 남김.

- 이후 시작 나이·입춘 위치 보정과 주기 계산으로 확장해 현재는 초기 배열을 그대로 표시하지 않고 다음 규칙으로 계산함.

| 구분 | 기준 |
| --- | --- |
| 초기 Excel 이식 | 대응 가능한 시점·흐름 값 38개 연결 |
| 현재 내부 계산 | `POINT_COUNT = 41`, 오프셋 `0, 2, 5, 7, …, 95, 97, 100`의 100년 범위 |
| 현재 흐름 계산 | 24개 시점의 기본 주기를 시작 절기에 맞춰 반복하고, 흐름별로 4개 시점씩 이동 |
| 화면 표시 | 내부 시작 나이 0·1세는 41개, -1세는 첫 음수 지점을 제외한 40개 표시 |

초기 이식 당시의 데이터 정렬 문제와 현재 주기 기반 계산을 구분해 기록함. 관련 기준은 [초기 판단 기록](docs/decision-log.md), [현재 상수](src/constants/config.ts), [주기 데이터](src/constants/cycleData.ts)에서 확인할 수 있음.

### 2. “모두 1세부터 표시” 요구와 입춘 정렬 조건의 조율

의뢰인은 모든 그래프가 1세부터 시작하기를 요청했으나, 시작점 라벨만 바꾸면 연도·나이·절기의 대응 관계가 어긋나는 문제가 있었음. 입춘 위치와 절기별 시점을 유지하기 위해 의뢰인과 협의하고, 내부 계산 시작점과 화면 표시 시작점을 구분함.

| 입력한 입춘 나이 | 내부 계산 시작 | 화면 표시 시작 |
| --- | --- | --- |
| 5로 나눈 나머지가 1·3: 1·3·6·8·11·13세 등 | 1세 | 1세 |
| 5로 나눈 나머지가 0·2: 2·5·7·10·12·15세 등 | 0세 | 0세 |
| 5로 나눈 나머지가 4: 4·9·14·19세 등 | -1세 | 음수 지점을 제외하고 1세 |

- 예를 들어 입춘 나이가 7세이면 `0 → 2 → 5 → 7세`로 계산·표시함. 9세이면 내부적으로 `-1 → 1 → 4 → 6 → 9세`로 계산하되 화면에는 `1 → 4 → 6 → 9세`부터 표시함. 0세는 유지하고 음수 나이만 화면에서 제외함.

연도 보정 시 생년을 임의로 이동하지 않고, 생년이 1세가 되는 해라는 기준을 유지함. -16세 입력과 2003년 보정 사례 등을 회귀 테스트에 반영함. 표시 조건은 [계산 로직](src/logic/calculateConsultation.ts)에서 확인할 수 있음.


## 3. 기술 선택과 역할

| 기술 | 적용 내용·선택 근거 |
| --- | --- |
| React | 입력·결과·출력 화면 구성, 흐름 선택과 정보 수정 상태 관리 |
| TypeScript | 연도·나이·절기·흐름 데이터와 계산 입출력 구조 정의 |
| Electron | Windows 설치형 앱, 오프라인 실행과 결과지 저장·인쇄 제공 |
| Apache ECharts | 네 흐름 비교, 표시 선택, 툴팁, 구간 확대·이동 구현 |
| Vite | 개발 환경과 배포용 화면 빌드 구성 |
| Vitest | 계산 로직의 경계값·회귀 테스트 자동화 |

사용 장소와 사용자가 한정된 환경을 고려해 중앙 서버와 로그인 없이 실행하는 방식을 선택함. 계산 기준은 로직에서 관리하고, 화면 표시와 결과지 출력은 각각의 용도에 맞춰 구성함.

## 4. 검증

Excel 첫 번째 시트의 연도·나이·24절기와 네 흐름 값을 비교해 초기 계산 기준을 확인함. 이후 합의한 개선 규칙은 자동 테스트와 실제 화면·출력 검증으로 확인함. 초기 Excel 비교와 현재 변경 규칙의 검증은 구분함.

| 검증 영역 | 확인 내용 | 기록된 결과 |
| --- | --- | --- |
| 계산 경계값 | -16세 입력, 입춘 나이 1~15세, 2003년 연도 보정 | 관련 자동 테스트 통과 |
| 계산 관계 | 10년 간격 유지, 24절기 반복, 연도·나이 정렬 | 관련 자동 테스트 통과 |
| 입력 처리 | 이름 공백 제거 | 관련 자동 테스트 통과 |
| 화면 | 화면 캡처를 통한 결과 표시 확인 | 최종 테스트 보고서상 통과 |
| 결과지 | PDF·PNG 생성, A4 가로 인쇄용 레이아웃 | 최종 테스트 보고서상 통과 |
| 배포 구성 | 설치 파일과 ZIP 구성 | 최종 테스트 보고서상 통과 |

2026.10.11. 기록 기준 `npm test` 실행 결과 1개 파일·34개 테스트 통과. 자동 테스트는 계산 규칙을 검증하며, 화면·출력·배포 검증은 별도로 진행함. 인쇄용 결과지 검증과 실제 프린터 출력 검증은 구분해 관리함.

네 시트의 그래프를 한 화면에서 비교하고, 행 숨김·표시 작업을 흐름 선택 기능으로 대체함. 기존에 그래프를 손으로 그려 카카오톡으로 보내던 업무는 PDF·PNG 결과지 저장 후 전송하는 방식으로 개선함.

## 6. AI 도구 활용과 직접 수행한 판단

개발자는 문제 정의, 기능·디자인 요구사항, 계산·표시 기준 협의와 검증 기준을 담당함. AI 도구는 Excel 구조 분석, React·TypeScript·Electron 코드 작성, UI 개선, 테스트 케이스 작성과 문서 정리에 활용함.

AI가 생성한 결과는 Excel 원본 비교, 자동 테스트, 실제 화면 캡처, PDF·PNG 출력과 설치 파일 검증으로 확인함. 데이터 대응과 입춘 정렬처럼 해석이 필요한 기준은 의뢰인과 협의해 결정하고 검증에 반영함.

## 7. 실행과 빌드

```bash
npm install
npm run dev
```

개발 서버 기본 주소: `http://127.0.0.1:5173`.

```bash
npm test
npm run typecheck
npm run build
```

Windows 설치 파일 생성:

```bash
npm run dist
```

설치 파일은 `release` 폴더에 생성됨.
