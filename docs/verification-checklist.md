# README 4-1 체크리스트 테스트

## 검증 체크리스트

- 아래 항목은 충족해야 하는 검증 기준임. 체크 표시는 완료 결과를 뜻하지 않으며, 실제 실행 결과와 미검증 범위는 아래 항목별 대응 및 실행 결과에 기록함.

### 계산과 데이터 대응

- [ ] 초기 Excel 대응에서 첫 번째 시점 C열에 첫 번째 흐름 값 B열을 연결하고, 이후 시점과 값도 순서대로 일치해야 함.

- [ ] 각 시점의 나이·연도·절기·네 흐름 값이 동일한 주기 위치에 대응하고, 흐름 값에 누락이 없어야 함.

- [ ] 모든 시점에서 `연도 = 기준 연도 + 나이 - 1`을 만족하고, 시작점 보정 때문에 입력한 기준 연도가 바뀌지 않아야 함.

- [ ] 양수 입춘 나이 1~15세 각각에서 입력한 나이가 입춘 지점에 정확히 표시되어야 함.

- [ ] 7세 입력은 `0 → 2 → 5 → 7세`, 9세 입력은 내부 `-1 → 1 → 4 → 6 → 9세`를 유지하며 화면에는 `1 → 4 → 6 → 9세`부터 표시되어야 함.

- [ ] 음수 입력은 원본의 2년·3년 간격과 절기 순서를 유지해야 함. -16세는 `1 → 4 → 6 → 9세`, -3세는 `2 → 4 → 7 → 9세`부터 표시되어야 함.

- [ ] 음수 나이는 화면에서 제외하되 0세는 유지하며, 모든 입력을 임의로 1세 시작으로 바꾸지 않아야 함.

- [ ] 24개 시점마다 절기와 흐름 값이 반복되고, 수단·재물·명예는 심리보다 각각 4·8·12칸 이동하여 흐름 간 10년 간격을 유지해야 함.

- [ ] 내부 계산 시점은 41개여야 함. -1세 지점을 숨기는 경우 화면 표시 시점은 40개가 되어야 하며, 내부 개수와 표시 개수를 구분해야 함.

<br>

### 화면·저장·인쇄·실행

- [ ] 이름 앞뒤 공백을 제거하고, 입력 오류를 표시하며, 정보 수정 시 기존 입력값을 유지해야 함.

- [ ] 최초에는 심리 흐름만 표시되고, 흐름 선택을 바꾸면 선택한 선만 그래프에 표시되어야 함.

- [ ] 그래프·툴팁·탐색 막대가 같은 시점의 나이·연도·절기·흐름 값을 가리켜야 함.

- [ ] 확대·이동·전체 보기 전환 후에도 시점과 값의 대응이 달라지지 않아야 함.

- [ ] PDF·PNG 결과지의 고객 정보와 흐름 값이 화면의 상담 결과 및 출력 설정과 일치해야 함.

- [ ] 인쇄용 PDF는 A4 가로 1페이지에 텍스트와 그래프가 잘림·겹침·누락 없이 표시되어야 함.

- [ ] 실제 프린터에서도 결과지가 정상 출력되어야 하며, PDF 생성 확인과 별도로 검증해야 함.

- [ ] 전달용 설치 파일은 고객 PC에서 설치·실행되어야 하고, Excel 설치나 인터넷 연결 없이 계산과 결과지 저장을 사용할 수 있어야 함.

## 1. 실행 방법

```bash
npm test
npm run test:checklist:ui
npm run test:checklist:pdf
```

- UI 테스트는 최신 빌드의 로컬 HTML을 숨김 Electron 창에서 실행함. HTTP·HTTPS 요청을 차단하므로 개발 서버나 인터넷 없이 화면 동작을 확인함.
- PDF 테스트는 UI 테스트에서 생성한 `artifacts/checklist/report.pdf`를 검사함. 기존 프로젝트의 `.guide-deps`에 있는 PyMuPDF가 필요함.
- UI 결과는 `artifacts/checklist/results.json`, 생성한 그래프는 `chart.png`, PDF 미리보기는 `report-preview.png`에 저장됨. 이 파일은 실행 때 갱신되는 검증 산출물임.

| C02 | 시점·나이·연도·절기·네 흐름 대응 | 기존 계산 테스트의 원본 주기 위치 비교와 신규 테스트의 값 누락·유한수 확인 |

| C07 | 음수 숨김·0세 유지 | 표시 구간 전체가 0세 이상인지 확인하고, 7세 입력에서 0세가 남는지 확인 |

| C09 | 내부 41개·표시 40개 구분 | 입력 23종에서 내부 41개를 확인하고, 내부 -1세 시작인 경우 표시 40개를 확인 |

계산 검증은 `src/logic/calculateConsultation.test.ts`와 `src/logic/verificationChecklist.test.ts`에서 실행함. C01은 코드에 보존한 원본 데이터와의 비교이며, 현재 Excel 파일을 열어 셀 값을 다시 추출·계산하는 테스트는 아님.

| U02 | 최초 심리 표시·흐름 선택 | 실제 화면의 기본 선택·모두 선택·모두 해제 상태, 차트 옵션의 선택한 시리즈 목록 |
| U03 | 그래프·툴팁·탐색 시점 일치 | -16·-3·7·9세의 모든 시점에서 축 라벨·툴팁 formatter·시리즈·인덱스 변환 검사, 실제 화면의 첫 구간 표시 검사 |
| U04 | 확대·이동·전체 보기 | 실제 구간 이동·전체 보기·화면 맞춤 전환, 모든 표시 인덱스의 내부 인덱스 왕복 변환. 마우스 휠·드래그 조작 자체는 미검증 |
| U05 | 결과지와 상담 결과 일치 | 화면·출력 옵션의 시리즈 값 비교, 결과지 고객 정보·선택 범례·이미지 연결, 실제 인쇄 준비에서 4200×1980 PNG 생성 및 비어 있지 않은 픽셀 확인 |
| U06 | A4 가로 1페이지·잘림·누락 | PDF 페이지 수·실제 A4 크기·고객 텍스트·그래프 이미지·페이지 내부 콘텐츠 검사. 렌더링 미리보기도 육안 확인함 |
| U07 | 실제 프린터 출력 | 수동 검증 필요. 자동 테스트는 `skip` 처리 |
| U08 | 고객 PC 설치·오프라인 실행 | 로컬 빌드의 네트워크 차단 실행은 확인. 고객 PC에서 설치 파일 실행은 수동 검증 필요, 자동 테스트는 `skip` 처리 |

PNG 검증은 인쇄용 그래프 이미지 생성에 대한 검증임. 고객의 파일 저장 대화상자 조작, Microsoft Print to PDF 선택 및 저장, 실제 프린터 출력까지 자동화한 것은 아님. 툴팁은 실제 formatter 결과를 검사하며, 마우스 hover 조작은 별도로 확인해야 함.

## 4. 실행 결과

- 2026.10.11. Vitest: 기존 42개 + 신규 36개 = **78개 통과**, 수동 검증용 2개 건너뜀.
- Electron 화면 테스트: **9개 통과**, 콘솔 오류 없음.
- PDF 구조 검사: 통과. 생성한 미리보기에서 고객 정보·범례·그래프·하단 연락처의 눈에 띄는 잘림·겹침 없음.
- TypeScript 타입 검사와 최신 빌드: 통과.
- 설치 파일은 재생성하지 않았으며, 고객 PC·실제 프린터·파일 저장 대화상자는 이번 검증에 포함되지 않음.
