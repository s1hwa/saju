# UI/UX Redesign Handoff Guide

이 문서는 다른 디자이너 또는 프론트엔드 개발자가 기존 계산 기능을 훼손하지 않고 화면을 전면 재설계하기 위한 인계 자료다.

## 1. 작업 목표

현재 화면을 다듬는 수준이 아니라 입력 화면과 결과 화면의 시각 체계를 다시 설계한다.

완성된 제품은 사주 상담 가게에서 상담자가 손님에게 직접 보여주는 Windows 데스크톱 프로그램이다. 일반 웹사이트나 홍보용 랜딩 페이지가 아니며, 상담 중 반복해서 사용하는 실무 도구여야 한다.

핵심 인상:

- 전문 상담 도구
- 세련되고 깔끔한 느낌, 전문적
- 그래프와 상담 내용에 집중
- 처음 보는 사람도 조작 방법을 바로 이해할 수 있음

## 2. 현재 디자인의 문제점

현재 UI는 기능 확인용 초안으로 취급한다. 그대로 스타일만 조금 바꾸는 방식은 피한다.

- 일반적인 관리도구나 SaaS 템플릿처럼 보여 제품 고유의 인상이 약하다.
- 입력 화면의 좌우 분할 패널과 장식용 곡선이 기능적 의미 없이 공간을 차지한다.
- 화면 크기에 비해 정보 밀도가 낮고 빈 공간이 많다.
- 브랜드 마크, 색상, 타이포그래피가 임시 구성에 가깝다.
- 결과 화면에서 고객 정보, 시리즈 선택, 내보내기 기능의 우선순위가 충분히 정교하지 않다.
- 긴 그래프를 단순 가로 스크롤로 처리해 중요한 시점을 탐색하기 불편하다.
- 상담자가 손님에게 화면을 설명하는 상황에 필요한 집중감과 완성도가 부족하다.

## 3. 절대 변경하면 안 되는 것

디자인 작업 중 아래 계산 계약은 수정하지 않는다.

- 분석 대상은 Excel의 첫 번째 워크시트뿐이다.
- 입력값은 `이름`, `입춘의 년도`, `나이`다.
- 간격 기준은 현재 `10년` 고정이다.
- 결과는 정확히 38개 시점이다.
- 절기, 연도, 나이, 심리, 수단, 재물, 명예 값은 기존 계산 엔진 결과를 사용한다.
- 38개 X축 정보에는 Excel `C:AN`이 대응한다.
- 흐름 값은 사용자와 합의한 Excel `B:AM` 38개를 사용한다.
- 설명 정보가 없는 Excel `AN41:AN44`의 추가 값 1개씩은 사용하지 않는다.
- 흐름의 앞부분에 있는 `null`은 0으로 바꾸지 않는다.
- 사주 지식으로 새로운 계산 공식을 만들지 않는다.

근거 문서:

- `docs/excel-analysis.md`
- `docs/decision-log.md`

보호 대상 코드:

- `src/logic/**`
- `src/constants/cycleData.ts`
- `src/constants/solarTerms.ts`
- `src/logic/calculateConsultation.test.ts`

디자인 작업자가 위 파일을 변경해야 한다고 판단하면 먼저 변경 이유와 예상 결과를 설명하고 승인을 받아야 한다.

## 4. 반드시 유지할 기능

### 입력 화면

- 프로그램 실행 즉시 상담 정보 입력 화면 표시
- 이름 입력
- 입춘의 년도 입력
- 나이 입력
- 유효성 오류 표시
- 분석하기
- 정보 수정 후 기존 입력값 유지

### 결과 화면

- 고객 이름
- 입춘 기준 연도
- 상담 날짜
- 절기, 연도, 나이를 함께 보여주는 그래프
- 심리, 수단, 재물, 명예 선택 컨트롤
- 정보 수정
- 새 상담
- PDF 저장
- 인쇄
- PNG 저장
- 저장 및 인쇄 처리 상태 표시

### 시리즈 선택 규칙

- 최초 결과 화면에서는 `심리`만 선택한다.
- `수단`, `재물`, `명예`는 기본 미선택이다.
- 체크하면 해당 선이 추가되고, 체크 해제하면 제거된다.
- 데이터 자체를 삭제하는 동작이 아니다.
- 현재 선택한 시리즈만 그래프, 툴팁, PDF, 인쇄물, PNG에 포함한다.
- 모든 항목을 해제했을 때 명확한 빈 상태를 표시한다.

## 5. 그래프 디자인 요구사항

그래프는 결과 화면에서 가장 중요한 요소다.

- Apache ECharts를 유지한다.
- 실제 데이터 지점은 절대 변경하지 않는다.
- 선은 뾰족한 꺾은선보다 모서리만 완만한 곡선으로 표현한다.
- 현재 기준은 `smooth: 0.32`이며 `smoothMonotone`은 쓰지 않는다. 직선 구간은 직선으로, 꼭짓점만 완만하게 표현한다.
- 곡선이 원래 최댓값이나 최솟값을 넘어선 것처럼 보이면 안 된다.
- 네 시리즈는 색상만으로 구분하지 않고 체크 상태, 이름, 선 표식 등도 함께 사용한다.
- 툴팁에는 절기, 연도, 나이와 현재 선택한 흐름값을 표시한다.
- 양수는 `+12.5`, 음수는 `-5`처럼 읽기 쉽게 표시한다.
- X축의 절기, 연도, 나이를 손님이 실제로 읽을 수 있어야 한다.
- 38개 지점을 무조건 한 화면에 억지로 압축하지 않아도 된다.
- 화면용 탐색 방식으로 줌, 구간 이동, 포커스 탐색 또는 가로 스크롤을 재설계할 수 있다.
- PDF와 인쇄물에는 38개 전체 흐름을 확인할 수 있어야 한다.
- 그래프가 빈 캔버스이거나 시리즈가 한 색으로 겹쳐 보이지 않는지 실제 렌더링으로 확인한다.

현재 그래프 구현:

- `src/components/FlowChart.tsx`
- SVG 렌더러 사용
- PNG 저장 시 고해상도 비트맵으로 변환

## 6. 재설계 자유 범위

다음 영역은 기존 모습에 얽매이지 않고 변경할 수 있다.

- 버튼 문구와 아이콘 배치
- 상태 메시지와 빈 상태
- 프로그램명 및 임시 브랜드 표현

## 7. 권장 디자인 방향

아래는 분위기 가이드이며 특정 색이나 레이아웃을 강제하지 않는다.

- 조용한 편집 디자인과 전문 분석 도구의 중간 지점
- 장식보다 정보의 리듬과 타이포그래피로 고급스러움 표현
- 웜 화이트만으로 화면 전체를 채우지 말고 중성색과 시리즈 색상의 균형 확보
- 고객명과 그래프는 강하게, 설정과 보조 정보는 조용하게
- 상담자가 그래프를 가리키며 설명하기 쉬운 구조
- 결과 화면은 넓은 모니터에서 정보가 지나치게 흩어지지 않도록 최대 폭과 정렬 기준 설정
- 버튼은 명령의 중요도에 따라 1차, 2차, 위험 없는 보조 동작으로 구분
- 내보내기 기능은 자주 쓰되 그래프보다 먼저 눈에 띄지 않게 배치

피해야 할 것:

- 엑셀 표처럼 보이는 UI
- 흔한 로그인 카드 또는 랜딩 페이지 구성
- 의미 없는 반원, 파형, 원형 장식
- 과도한 금색, 한자, 용, 도장, 점술 장식
- 보라색 중심의 AI 서비스 스타일
- 베이지색만 반복되는 단조로운 화면
- 큰 둥근 카드가 겹쳐 있는 구조
- 지나친 그림자와 그라데이션
- 작은 패널 안의 과도하게 큰 제목
- 사용법을 길게 설명하는 안내문
- 아이콘으로 충분한 기능을 텍스트 캡슐 버튼으로 남발하는 방식

## 8. 화면별 설계 기준

### 입력 화면

- 첫 화면에서 바로 입력할 수 있어야 한다.
- 홍보 문구나 큰 히어로 영역을 만들지 않는다.
- 세 입력값과 분석 버튼의 시선 흐름이 분명해야 한다.
- 숫자 입력은 단위와 의미가 혼동되지 않게 한다.
- 키보드만으로도 자연스럽게 입력하고 제출할 수 있어야 한다.
- 빈 화면, 오류 상태, 수정 상태를 확인한다.

### 결과 화면

- 첫 시선은 고객명과 그래프로 이동해야 한다.
- 심리만 기본 표시된 상태가 명확해야 한다.
- 다른 흐름을 추가하는 동작이 그래프 가까이에 있어야 한다.
- 정보 수정과 새 상담은 서로 혼동되지 않아야 한다.
- PDF, 인쇄, PNG는 하나의 내보내기 그룹으로 정리할 수 있다.
- 1100×720에서도 컨트롤이 겹치거나 잘리지 않아야 한다.
- 1440×900과 1920×1080에서 지나치게 비어 보이지 않아야 한다.

### 인쇄 및 PDF

- 화면을 그대로 출력하지 않는다.
- A4 가로 전용 결과지를 유지하거나 더 개선한다.
- 고객명, 상담일, 입춘 기준 연도, 선택한 범례, 그래프를 포함한다.
- 앱의 내비게이션과 버튼은 출력하지 않는다.
- 로고와 상호를 나중에 교체할 수 있는 영역을 마련한다.
- 출력 미리보기에서 한 페이지에 안정적으로 들어오는지 확인한다.

## 9. 접근성과 조작 기준

- 체크박스의 선택 상태를 색상에만 의존하지 않는다.
- 모든 폼 요소에 연결된 라벨을 둔다.
- 키보드 포커스가 명확해야 한다.
- 본문과 컨트롤의 색 대비를 확보한다.
- 아이콘 단독 버튼에는 `aria-label` 또는 툴팁을 제공한다.
- 텍스트가 버튼이나 패널 밖으로 넘치지 않게 한다.
- 클릭 시 레이아웃 크기가 바뀌거나 그래프가 흔들리지 않게 한다.

## 10. 기술 조건

- React + TypeScript + Electron + Vite + ECharts 유지
- 오프라인 실행
- 외부 CDN, 웹폰트, 원격 이미지 사용 금지
- `any` 사용 최소화
- 계산 로직을 React 컴포넌트에 복사하지 않음
- Electron의 PDF, 인쇄, PNG IPC 계약 유지
- `contextIsolation: true`, `nodeIntegration: false` 유지
- Lucide에 해당 아이콘이 있으면 직접 SVG를 만들지 않고 Lucide 사용

## 12. 완료 조건

- 계산 테스트가 모두 통과한다.
- 심리만 선택된 초기 결과 화면이 정확하다.
- 수단, 재물, 명예를 각각 추가하고 제거할 수 있다.
- 네 시리즈를 동시에 켜도 색과 선이 구분된다.
- 곡선이 부드럽지만 원본 데이터 지점을 왜곡하지 않는다.
- 입력 화면과 결과 화면이 1100×720에서 겹치지 않는다.
- 1440×900에서 정보 밀도와 시각적 균형이 좋다.
- PDF, 인쇄, PNG가 현재 선택한 시리즈를 반영한다.
- 새 상담은 입력을 초기화하고, 정보 수정은 기존 입력을 보존한다.
- 콘솔 오류가 없다.
- `docs/design-system.md`를 새 디자인 기준으로 갱신한다.

아래 문구와 이 문서를 함께 전달하면 된다.

> 이 Electron 상담 프로그램의 UI/UX를 전면 재설계해 주세요. 현재 화면은 기능 확인용 초안이므로 시각 디자인을 그대로 따르지 않아도 됩니다. `docs/ui-redesign-handoff.md`, `docs/excel-analysis.md`, `docs/decision-log.md`를 먼저 읽고, 계산 로직과 38개 데이터 계약은 절대 변경하지 마세요. 상담 현장에서 손님에게 직접 보여줄 수 있는 전문적이고 고유한 화면을 만들고, 입력·결과·그래프·A4 출력까지 실제 렌더링으로 검증해 주세요.
